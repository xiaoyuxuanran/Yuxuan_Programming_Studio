# 第43～50课 ESP32 配套固件

参考硬件为原始 ESP32-WROOM DevKit。本资料已完成 Arduino ESP32 Core 2.0.17、板型 `esp32:esp32:esp32` 的六份固件编译，以及桌面协议测试；未连接开发板和 Android 手机。Core 3 的适配分支尚未在本次编译验证。

## 接线

接线前断开开发板电源，共地后再上电。

|器件|接线|用途|
|---|---|---|
|普通LED|GPIO23 → 330Ω电阻 → LED正极；负极 → GND|开关和8位PWM调光|
|10kΩ电位器|两端接3.3V和GND，滑端接GPIO34|ADC1原始读数0～4095|
|按钮|GPIO27与GND之间；内部INPUT_PULLUP|松开1，按下0|
|USB|开发板接电脑|烧录与115200波特串口观察|

GPIO34输入不超过3.3V。不要把GPIO接到5V。不同型号开发板的丝印和可用引脚须按其原理图核对。本课ADC没有温度换算或精密电压标定。

## 课次与烧录文件

用平台的 Mixly Arduino ESP32 环境或已配置的 Arduino 工具链打开对应 `.ino`，选择原始ESP32板型、实际USB端口后编译并上传。文件夹中头文件须与 `.ino` 保持在一起，不要只拷贝单个文件。

|课次|文件夹|手机侧操作|
|---|---|---|
|43|43-serial-protocol|APP生成、粘贴解析指令；USB串口实际由电脑操作|
|44～45|44-45-classic-spp|系统配对YX-ESP32-SPP，APP再连接|
|46|46-ble-led|扫描YX-ESP32-BLE，连接并订阅TX通知|
|47|47-tcp-ap|手机加入YX-ESP32-AP；口令YXclass88；TCP 192.168.4.1:9000|
|48|48-tcp-sta|先改WIFI_SSID/WIFI_PASSWORD；电脑串口读取板子的实际IP；端口9000|
|49～50|49-50-tcp-reliable|默认STA，同样先填路由器信息；带序号v2协议。改YX_USE_SOFT_AP为1可使用AP|

经典SPP固件用于原始ESP32，不能直接用于不具备经典蓝牙SPP的C3/S3。BLE与SPP是不同通信方式。

## 串口、SPP和TCP v1

命令末尾附一个实际LF换行字节；调试器选择“换行”发送，不是输入两个可见字符 `\n`。

|请求|应答示例|含义|
|---|---|---|
|LED,1|OK,LED,1|开灯并设PWM=255|
|LED,0|OK,LED,0|关灯并设PWM=0|
|PWM,128|OK,PWM,128|PWM设128；非零时LED状态为1|
|GET|STATE,1,128,2048,1|LED、PWM、ADC、按钮|
|PING|PONG|协议探测|
|PWM,256|ERR,BAD_VALUE|数值越界，不改变输出|

完整命令最多64字符，不含LF；允许末尾CRLF。超长帧丢弃至下一LF，返回ERR,TOO_LONG。空行忽略。接收必须按LF提取完整行；一次收到的片段可能是半行或多行。

## BLE服务与特征

|用途|UUID|
|---|---|
|服务|6e400001-b5a3-f393-e0a9-e50e24dcca9e|
|RX写入|6e400002-b5a3-f393-e0a9-e50e24dcca9e|
|TX通知/读取|6e400003-b5a3-f393-e0a9-e50e24dcca9e|

连接后 `RegisterForStrings(服务UUID, TX UUID, false)`。`NullTerminateStrings=false`；调用 `WriteStringsWithResponse(服务UUID, RX UUID, false, 含文字"1"的单项列表)` 开灯，列表含"0"则关灯；不带LF或NUL。合法写入后TX通知 `LED,1` / `LED,0`；非法写入通知ERR。写入完成回调不等于灯的应用层确认。设备断开后重新广播。Android权限与具体手机兼容性按任务单另验。

## TCP v2：序号与一次重试

请求 `12|LED,1` 加LF，应答 `12|OK,LED,1` 加LF。序号1～2147483647；一次只允许一条待确认命令。

- 同序号、同指令：返回缓存应答，不重新执行。
- 同序号、不同指令：ERR,SEQ_REUSE；旧序号：ERR,STALE_SEQ。
- APP等待1500ms后只重发同一原文一次，再超时显示“结果未确认”。超时不证明设备没执行。
- 断开连接清半行与待确认，重新连接重建序号会话。设备保留输出；APP需GET取得实际状态。
- 第50课超过10秒未收到有效STATE，标记旧状态；不能把历史值称为实时读数。

## 电脑TCP课堂测试服务

`tcp_lab_server.py` 仅用Python标准库，支持3.8与3.13。模拟ADC恒为2048、按钮恒为1，没有真实GPIO。它用于检查APP的TCP解析与反馈，不能替代ESP32实测。

```powershell
python tcp_lab_server.py --host 0.0.0.0 --version 2 --scenario split
```

手机与电脑在可互通局域网，APP填写电脑的实际IPv4和9000端口。47/48课改 `--version 1`。`--scenario` 可选normal（正常）、split（拆成两段发送）、combined（同一应答发两遍）、delay（延迟1.8秒）、old（先发上一条旧应答）、close（收到后关闭）。操作系统可能重新合并TCP片段；不能把一次send等同一次DataReceived。combined场景的重复应答用于检验清等待后不重复更新。

测试服务默认仅绑定127.0.0.1，手机课堂须显式加 `--host 0.0.0.0`；只作为教学环境测试程序。
