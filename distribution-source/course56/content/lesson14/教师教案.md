# 第14课｜程序侦探挑战

**项目：运动积分器的三类故障修复　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | YXCourse14.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | YXCourse14Class.aia：保留完整组件界面、全部变量、过程与事件；故意保留三项逻辑缺陷；AddButton.Click 固定2改为得分+2；刷新过程的GT改为GTE；重置过程改为得分=0后调用刷新。 |
| 纯界面起始版 | YXCourse14Starter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 把操作、预期与实际分开记录，建立可复现故障。
2. 追踪变量→条件→显示，修复累计、边界与重置。
3. 每次只改一个原因，并用全部测试做回归检查。

## 示例边界

每完成一次课堂运动挑战加2分，达到10分即达标。Class版恰好包含固定赋值、遗漏等号、假重置三种逻辑错误；学生依据证据逐项修复。

本课Class版有意保留三处逻辑故障，积木结构应可导入；完整答案版修复全部三处，Starter版只有界面。修复不涉及体育能力评价，也不要求学生超出教师安排进行运动。

## 教师故障清单与修复顺序

课堂支架有意保留以下三处逻辑错误；完整答案没有这些故障。按累计、边界、重置的顺序修复，避免前一项遮挡后一项。

| 位置 | 故障 | 修复答案 |
| --- | --- | --- |
| `AddButton.Click` | 得分固定设为2 | 得分←得分+2 |
| `刷新` | 使用>目标，10分不达标 | 比较改为≥目标 |
| `重置` | 只清标签，没有清全局得分 | 设置得分为0，再调用刷新 |

学生任务单不直接列出此答案表；先让学生记录操作、预期和实际，再提出定位假设。

## 核心任务与参考答案

### 任务1：修复永远只有2分

1. 导入故障Class版，从0连续点加分两次，记录预期4与实际。
2. 找到AddButton.Click中得分固定设2。
3. 改为得分←得分+2，保留随后调用刷新，重新测试两次。

提问：为什么不能先去改ScoreLabel的文字？

参考：根因是变量没累计，改显示不能修复源数据；应修赋值表达式。

### 任务2：修复刚好10分不达标

1. 在累计修好后，从0加分五次，检查10分状态。
2. 找到刷新过程中得分>目标的比较。
3. 改成≥目标，再测试8、10、12的反馈。

提问：为什么应先修累计，再查10分边界？

参考：原故障把得分每次固定2，无法通过正常操作到10；它会掩盖边界故障。

### 任务3：修复重置后的旧分数

1. 加到10分后点重置，再加一次，记录是否回到旧分。
2. 找到重置过程只改标签的做法，改为得分←0并调用刷新。
3. 从头复测2次、5次、重置再1次三条用例，保存修复说明。

提问：重置后标签写0还不够的证据是什么？

参考：下一次加分读取旧全局得分，会跳到旧分+2；只有变量清零再刷新才恢复真实初始状态。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| ScoreLabel | Label | 显示分数 |
| AddButton | Button | 运动一次加2 |
| StatusLabel | Label | 显示是否达标 |
| ResetButton | Button | 重新开始 |

- 当 `AddButton.Click`：得分=得分+2；刷新。
- 当 `ResetButton.Click`：重置。

## 过程定义的教学核对

- `刷新`：显示得分；若得分>=目标显示达标，否则继续努力。
- `重置`：得分=0；刷新。

请同时对照上方“三个工程版本”区分已给结构与学生任务，不把完整支架重复布置为缺失内容。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 同时随机改许多积木 | 先复现，确认一项根因后只改一处，再测。 |
| 点一次加分就说累计正常 | 固定2在第一次也正确，至少连点两次。 |
| 只测8与12 | 遗漏刚好10的等号边界。 |
| 重置后看一眼0就通过 | 还需再加一次，检查源变量。 |

## 分层与评价

- **基础：**按顺序修复三故障，保留操作、预期、实际和修改。
- **提高：**给同伴设计一条能区分正确与错误程序的最短测试。
- **拓展：**在个人副本故意改变一项规则，让同伴依据测试发现；明确这是练习故障，不交付为完整答案。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 为什么只点一次加分发现不了固定设2？
   参考：正确累计与固定2第一次都得到2，第二次才分成4和2。
2. 哪一个分数最能检查>与≥的差别？
   参考：10，刚好等于目标。
3. 修复后为什么还要重跑之前的测试？
   参考：确认新修改没有破坏已正确的功能，这是回归检查。
