# 第23课｜会说话的 APP

**项目：带语速和完成反馈的语音助手　时长：90分钟　配套课件：24页**

## 学习目标与达标证据

1. Speak接收文字，不接收音频文件。
2. 调用Speak后不会等待整段话结束。
3. 用测试记录验证会说话的 APP的核心规则。

## 示例边界

语音提示小助手：输入一段文字，选择语速并朗读，结束后恢复按钮。

语音由Android系统TTS引擎提供；中文离线朗读取决于已安装的语音数据。本课不生成音频文件。

## 核心任务与参考答案

### 任务1：补校验与朗读

1. 找到Class已给的恢复按钮、Stop与滑块事件。
2. 添加SpeakButton.Click：trim后为空只提示。
3. 有效时先手动停止←假、播报中←真，禁用SpeakButton。
4. 设置Voice.SpeechRate为滑块值，再Speak去空格后的文字。

提问：为什么不能在Speak后立刻写“朗读完成”？

参考：Speak是开始请求，整段结束由Voice.AfterSpeaking通知；调用返回不代表播放完成。

### 任务2：用已有语速事件做对照实验

1. 保留RateSlider.PositionChanged，并核对RateLabel。
2. 同一句分别用0.5、1、1.5倍朗读，记录听到的变化。
3. 检查SpeechRate在开始朗读时读取滑块，而非把显示文字当数值。

提问：语速标签更新，为什么还要在朗读时设置SpeechRate？

参考：标签只显示反馈；SpeechRate属性才控制引擎，本工程开始时读取当前滑块值。

### 任务3：补完成反馈并检查停止

1. 添加Voice.AfterSpeaking，先恢复按钮。
2. 手动停止为真时显示已停止；否则按result显示完成或语音不可用。
3. 长句中停止，再朗读，检查按钮可恢复。
4. 无语音设备只做事件追踪，听测栏写待测。

提问：停止后result=false，应直接判定引擎坏了吗？

参考：不应。先检查手动停止标志；停止引发的回调应保留已停止提示。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| MessageBox | TextBox | 输入待朗读文字 |
| RateSlider | Slider | 设置0.5到1.5倍语速 |
| SpeakButton | Button | 朗读 |
| StopButton | Button | 停止 |
| StatusLabel | Label | 播报状态 |
| Voice | TextToSpeech | 系统语音引擎 |
| RateLabel | Label | 显示当前语速倍率 |

- 当 `SpeakButton.Click`：若trim(MessageBox.Text)为空则提示；否则SpeechRate←滑块值；播报中true；按钮禁用；Speak(trim文字)。
- 当 `Voice.AfterSpeaking`：先恢复按钮；若手动停止则显示已停止，否则result真显示朗读完成，假显示语音不可用。
- 当 `StopButton.Click`：手动停止←真；Voice.Stop；恢复按钮；状态已停止。
- 当 `RateSlider.PositionChanged`：显示round(thumbPosition*10)/10倍率。

## 出口题参考

1. 三个空格会请求朗读吗？
   参考：不会，trim为空时只提示请先输入文字。
2. AfterSpeaking的result有什么用？
   参考：表示引擎报告的成功与否；需结合手动停止标志解释。
3. 没有中文语音包时编译成功能证明会说话吗？
   参考：不能，需在具备相应语言数据的设备听测。
