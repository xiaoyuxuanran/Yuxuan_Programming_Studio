### 过程职责（教师参考）

- `连接设备`：Connect(DevicePicker.Selection)返回true则开轮询和控制键，否则失败提示。
- `发送命令`：核对已连接及IsConnected后SendText(命令+LF)，只显示等待应答。
- `接收分帧`：追加片段，while提取所有LF完整行，保留半行，上限512字符。
- `清理连接`：清连接标志和缓存、关闭轮询、禁用控制。

### 三组真实积木截图

1. `DevicePicker.BeforePicking`：本入口已给；查找目标经典SPP设备。
2. `连接设备`：连接设备过程待补，清理与界面恢复结构可复用。
3. `发送命令`：发送命令待补；不是按键后直接显示成功。

### 设备与验证边界

配套固件及接线表见firmware。参考板为原始ESP32-WROOM DevKit；LED GPIO23串330Ω，ADC1 GPIO34只接0～3.3V电位器滑端，GPIO27按钮接地，0为按下。工程导入、APK编译和桌面协议测试不能代替Android与ESP32实物联调；本次未做真机测试。 经典蓝牙SPP只用于具备该能力的原始ESP32；C3/S3不适用此固件。系统先配对YX-ESP32-SPP，APP再Connect建立通道，BluetoothClient不同于BLE。

## 核心任务与参考答案

### 任务1：阅读配对设备入口

1. BeforePicking已给，读取Bt.AddressesAndNames。
2. 教师课前在系统配对YX-ESP32-SPP。
3. 指出配对列表与当前通道连接的区别。

提问：配对成功就等于APP已经连接吗？

参考：不是，还要APP调用Connect并检查返回值。

### 任务2：补连接设备过程

1. 先清理旧连接状态。
2. 调用Bt.Connect(DevicePicker.Selection)。
3. 返回真才设已连接、启用按钮和PollClock。
4. 失败只提示，不把已连接强设为真。

提问：BluetoothClient有Connected事件吗？

参考：本地原生组件没有该事件；这里用Connect返回值及IsConnected。

### 任务3：补发送命令

1. 同时检查已连接与Bt.IsConnected。
2. 命令附LF，再Bt.SendText。
3. 只显示等待应答；已给轮询按可用字节读取并分帧。
4. 主动断开后按钮禁用，重新选择可再连接。

提问：收到半行能用ReceiveText(-1)一直等吗？

参考：本例避免阻塞，按当前可用字节数读取，再交给缓存分帧。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| DevicePicker | ListPicker | 选择已配对设备 |
| DisconnectButton | Button | 断开 |
| OnButton | Button | 请求开灯 |
| OffButton | Button | 请求关灯 |
| StatusLabel | Label | 连接状态 |
| Bt | BluetoothClient | 经典蓝牙SPP |
| PollClock | Clock | 读取已到达字节 |

- 当 `DevicePicker.BeforePicking`：检查Available与Enabled；Elements←AddressesAndNames。
- 当 `DevicePicker.AfterPicking`：连接设备。
- 当 `OnButton.Click`：调用发送命令(LED,1)。
- 当 `OffButton.Click`：调用发送命令(LED,0)。
- 当 `PollClock.Timer`：IsConnected且BytesAvailableToReceive>0则ReceiveText(精确可用字节数)；处理新文本；失联则清理。
- 当 `DisconnectButton.Click`：断开清理。
- 当 `Screen1.PermissionDenied`：显示蓝牙权限需要并禁用控制。
