## 课堂支架与实际程序核对

已给结构：

- 类型选择与变量
- 结束请求/结束提交及超时错误恢复
- 提交反馈与GotText占位

学生要补或修正：

- 校验trim正文长度1～200，设置表单Content-Type
- BuildRequestData封装kind和message并PostText
- 201解析有效id后清稿，400/超时保留草稿

实际全局变量：`请求中`、`当前URL`、`类型`、`响应数据`。

### 过程职责（教师参考）

- `提交反馈`：验证长度；RequestHeaders←Content-Type:application/x-www-form-urlencoded；Body←BuildRequestData([[kind,类型],[message,文字]])；Url←/api/v1/feedback；PostText。
- `结束提交`：恢复按钮与请求中false。

### 三组真实积木截图

1. `提交反馈`：输入校验先于请求状态切换；表单头与编码方式一致。
2. `Http.GotText`：201分支解码id，错误分支保留输入。
3. `Http.TimedOut`：超时处理报告未确认并恢复操作，不调用PostText。

### 设备与验证边界

使用随课Python课堂服务，HostBox只填电脑局域网IPv4。示例不是公网服务；手机上的127.0.0.1指手机自身。服务的自动测试不等于Android客户端真机联调。 POST发送教学意见，不要求真实姓名或联系方式。超时表示结果未确认，本例不自动重发。

- 教师电脑运行配套Python标准库API，手机与电脑在可互通的同一局域网。
- 电脑本机可用127.0.0.1；手机必须填写教师电脑局域网IPv4，不能填127.0.0.1。
- HTTP用于隔离的课堂教学数据，不填写真实个人资料；Android明文HTTP兼容性以本平台打包结果实测。

### 共用课堂服务

教师使用随课 `teaching-api/teaching_server.py`；Python 3.8或3.13均可，无需第三方库。先在电脑浏览器核对欢迎接口。手机课堂运行 `python teaching_server.py --host 0.0.0.0`，使用电脑实际局域网IPv4。HostBox仅填IP，例如192.168.1.8；工程初值192.168.1.10是示例，不是固定地址。不要填协议、端口或路径；端口8765和接口路径由积木拼接。手机与电脑需在可互通的教学局域网，手机的127.0.0.1表示手机自身。

可重复故障：先停止当前服务，再加 `--scenario delay`（GET延迟6秒，对照APP超时5秒）、`error`（GET 500）、`empty`（空公告/活动）、`invalid-json`（坏JSON）。恢复用 `--scenario normal`。普通AIA按钮即可触发，不改HostBox为路径，也无需物理断网。POST超时不自动重发；先查结果再决定是否重试。示例仅教学数据，无账号权限系统，勿作为生产留言平台。

## 核心任务与参考答案

### 任务1：补校验与请求头

1. trim正文，长度须为1到200。
2. 设置RequestHeaders的Content-Type为application/x-www-form-urlencoded。
3. 请求中真并禁用发送按钮。

提问：为什么不能把空输入发给服务器再说？

参考：客户端先反馈可减少无效请求，服务端仍需独立校验。

### 任务2：补表单编码与成功回执

1. BuildRequestData处理kind和message两组键值。
2. PostText发送到/api/v1/feedback。
3. GotText只在201且回执id有效时显示已接收并清正文。
4. 编号可能已增长，不硬编码F0001。

提问：只检查HTTP 201就能忽略回执结构吗？

参考：不应，还要确认返回数据含有效id再显示本次成功。

### 任务3：保留失败草稿

1. 400和其他失败只显示原因、恢复按钮。
2. 超时保留正文并提示结果未确认。
3. 重新提交前先核对服务记录，不自动再次Post。

提问：超时为何不能直接说提交失败？

参考：请求可能已被服务器保存，只是回执没及时回来。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| HostBox | TextBox | 教师电脑局域网IPv4地址 |
| RequestButton | Button | 发起本课请求 |
| StatusLabel | Label | 请求与错误状态 |
| KindPicker | ListPicker | 选择反馈类型 |
| MessageBox | TextBox | 反馈正文 |
| ReceiptLabel | Label | 接收编号 |
| Http | Web | 教学HTTP客户端 |

- 当 `KindPicker.BeforePicking`：列表建议、问题、表扬。
- 当 `KindPicker.AfterPicking`：类型←Selection。
- 当 `RequestButton.Click`：若未请求中则提交反馈。
- 当 `Http.GotText`：201时解码id并显示已接收，清正文；400显示校验信息保留正文；其他码显示失败；结束提交。
- 当 `Http.TimedOut`：提示结果未确认，请先检查再重试；保留正文；结束提交。
