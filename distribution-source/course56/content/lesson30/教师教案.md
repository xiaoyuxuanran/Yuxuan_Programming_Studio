## 课堂支架与实际程序核对

已给结构：

- 全部变量
- 刷新并取消选择、选择有效
- 初始化和新增

学生要补或修正：

- TodoView.AfterPicking保存索引并载入内容，启用修改/删除
- UpdateButton.Click校验后替换列表项
- DeleteButton.Click删除后刷新并取消选择

实际全局变量：`任务`、`选中序号`。

### 过程职责（教师参考）

- `刷新并取消选择`：TodoView.Elements←任务；选中序号0；TaskBox清空；修改删除禁用。
- `选择有效`：返回1<=选中序号<=length任务。

### 三组真实积木截图

1. `TodoView.AfterPicking`：SelectionIndex先校验再读取；选择文字只是反馈，序号才定位。
2. `UpdateButton.Click`：替换前同时检查索引和非空内容，成功后统一刷新。
3. `DeleteButton.Click`：删除改变后续序号，取消选择是防止误删的关键。

## 核心任务与参考答案

### 任务1：选择并载入

1. 添加TodoView.AfterPicking，保存SelectionIndex。
2. 选择有效才select list item并填TaskBox。
3. 启用修改与删除，选择第二项核对文字。

提问：为什么保存序号而不只保存文字？

参考：重名条目仍可通过位置区分，修改和删除需要指定位置。

### 任务2：修改所选任务

1. 添加UpdateButton.Click，先调用选择有效。
2. trim输入非空才replace list item。
3. 调用刷新并取消选择；把读书20分钟改成30分钟。

提问：修改为什么不用add items？

参考：add会增加条目，replace才替换原位置且数量不变。

### 任务3：删除后取消选择

1. 添加DeleteButton.Click，检查索引有效。
2. remove list item后调用刷新并取消选择。
3. 连点两次删除，第二次不应再删下一项。

提问：删除后仍保存原序号有什么风险？

参考：后面的项目移位，旧序号可能指向另一任务。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| TodoView | ListView | 任务列表 |
| TaskBox | TextBox | 新增或修改内容 |
| AddButton | Button | 新增 |
| UpdateButton | Button | 修改选中项 |
| DeleteButton | Button | 删除选中项 |
| HintLabel | Label | 当前选择和提示 |

- 当 `TodoView.AfterPicking`：选中序号←SelectionIndex；输入框←select list item；修改删除启用。
- 当 `AddButton.Click`：非空则追加；刷新并取消选择。
- 当 `UpdateButton.Click`：选择有效且输入非空时replace list item；刷新并取消选择。
- 当 `DeleteButton.Click`：选择有效时remove list item；刷新并取消选择。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 改名变成新增 | 检查使用replace而不是add |
| 删除后一项也被删 | 修改后选中序号应归0 |

## 出口题参考

1. 选择有效检查哪两个边界？
   参考：序号至少1且不大于列表长度。
2. 修改后为什么清选择？
   参考：避免旧选择对后续编辑产生误导。
3. 如何证明连点不会误删？
   参考：删除一次后核对序号0、按钮禁用，再尝试第二次。
