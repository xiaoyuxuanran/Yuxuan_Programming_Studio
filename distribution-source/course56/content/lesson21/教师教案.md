# 第21课｜可以选择结局的故事

**项目：五场景双结局失物招领故事　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | YXCourse21.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | YXCourse21Class.aia：保留global 场景、显示场景分派和五个场景过程框架、校门与两种结局的完整显示、返回开头、初始化、重读、朗读；补写场景_操场和场景_办公室；添加ChoiceA.Click与ChoiceB.Click的互斥分支跳转；验证结局隐藏选项、重读恢复选项。 |
| 纯界面起始版 | YXCourse21Starter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 用场景变量决定同一个选择按钮的下一步。
2. 完成两个中间场景的显示及ChoiceA/B互斥跳转。
3. 测试两种结局、重读恢复与当前文本朗读。

## 示例边界

从校门发现失物出发，经过操场或办公室，到达找到主人或明天再找两种结局。统一显示当前场景，结局隐藏选择，重新阅读恢复校门；可朗读当前叙述。

实际工程把五场景显示拆为场景_校门、场景_操场、场景_办公室、场景_找到主人、场景_明天再找，显示场景(名称)负责互斥分派；全程一个Screen。共享原创校园插图作为导览，不假称每幕有不同实景照片。语音依赖设备中文TTS。

## 核心任务与参考答案

### 任务1：补中间两幕的显示

1. 导入Class版，找到场景_操场与场景_办公室占位。
2. 补标题、叙述、两个按钮Text及Visible真，保持与跳转图一致。
3. 读显示场景(名称)，说明它只调用一个匹配场景过程。

提问：为什么结局里隐藏了按钮，回校门时还要设真？

参考：Visible是运行状态，进入结局设假会保留；重新阅读必须主动恢复可见。

### 任务2：完成两组互斥跳转

1. 添加ChoiceA.Click：校门→操场、操场→办公室、办公室→找到主人。
2. 添加ChoiceB.Click：校门→办公室、操场或办公室→明天再找。
3. 使用if/else if互斥结构，测试一次点击只跳一幕。

提问：为什么三个独立if可能一次跨过多个场景？

参考：前一个if改变场景后，后面的if可能立即满足新值，导致同一点击连跳；互斥分支避免继续匹配。

### 任务3：结局、重读与朗读回归

1. 走A→A→A到找到主人，再从校门B→B到明天再找。
2. 分别点重新阅读，检查回校门且两个选择可见。
3. 点朗读这一幕，核对Voice.Speak使用当前SceneText；设备听觉另记实测或待测。

提问：朗读应该读固定第一幕文字，还是当前SceneText？

参考：当前SceneText，才能与屏幕场景一致；已有ReadButton事件负责Stop后Speak。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| SceneTitle | Label | 场景标题 |
| SceneText | Label | 对白与叙述 |
| SceneImage | Image | 场景插图 |
| ChoiceA | Button | 第一个选择 |
| ChoiceB | Button | 第二个选择 |
| RestartButton | Button | 重新阅读 |
| Voice | TextToSpeech | 可选朗读当前文本 |
| ReadButton | Button | 朗读当前叙述 |

- 当 `Screen1.Initialize`：显示场景(校门)。
- 当 `ChoiceA.Click`：校门→操场；操场→办公室；办公室→找到主人。
- 当 `ChoiceB.Click`：校门→办公室；操场→明天再找；办公室→明天再找。
- 当 `RestartButton.Click`：返回开头。
- 当 `ReadButton.Click`：Voice.Stop；Voice.Speak(SceneText.Text)。

## 过程定义的教学核对

- `显示场景(名称)`：场景←名称；使用互斥分支调用五个场景_名称小过程，各小过程同步设置当前显示与选项。
- `返回开头`：显示场景(校门)。

请同时对照上方“三个工程版本”区分已给结构与学生任务，不把完整支架重复布置为缺失内容。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 一次点击到结局 | 多个独立if在改状态后继续命中；改互斥分支。 |
| 正文是新幕，按钮还是旧幕 | 每个场景同步更新标题、正文与选项文字。 |
| 重读后选择按钮消失 | 非结局场景应主动设Visible真。 |
| 朗读与屏幕不一致 | Speak使用当前SceneText.Text，别写死第一幕。 |

## 分层与评价

- **基础：**补两幕与A/B跳转，两个结局都可重读。
- **提高：**改写一个选择的理由与后果，同时保持跳转图可追踪。
- **拓展：**增加第三结局前先更新场景图、状态分派、按钮与所有回归路径。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 校门点A一次应到哪里？为什么不能直接到结局？
   参考：操场；一次点击只选择一条互斥分支。
2. 进入结局后重新阅读要恢复什么？
   参考：场景变量、标题、正文、选择文字及Visible。
3. 共享插图不变时，用户如何知道当前场景？
   参考：靠明确的场景标题、叙述和选项文字；不只依赖图片变化。
