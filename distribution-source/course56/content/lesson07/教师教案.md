# 第7课｜会记数的 APP

**项目：合作积分器　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | YXCourse07.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | YXCourse07Class.aia：保留global 得分、刷新得分、AddButton.Click 的刷新调用；在 AddButton.Click 的刷新前加入累计赋值；添加 MinusButton.Click，限制最低 0 分；添加 ResetButton.Click，同时清变量和显示。 |
| 纯界面起始版 | YXCourse07Starter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 用全局变量得分保存当前积分，区分数据与显示。
2. 实现累计加分、最低0分的减分及归零。
3. 用连续操作预测变量变化，并检查重置后加分。

## 示例边界

初始0分，完成合作挑战加1分，撤销一次减1分且最低为0；归零开始新一轮。数据保存在本次运行的全局变量中。

刷新得分过程作为完整支架提供，第13课再细讲过程；本课重点是变量的读取、赋值和累计，不要求持久保存积分。

## 核心任务与参考答案

### 任务1：完成累计加分

1. 在Class版找到AddButton.Click中已给的刷新得分调用。
2. 在调用前加入“设置全局得分为：读取全局得分 + 1”。
3. 连续点三次，记录每次显示与变量预测。

提问：为什么赋值应在刷新调用之前？

参考：先刷新会显示旧值，变量改变后界面没有再次更新；应先改数据再显示。

### 任务2：读懂统一刷新

1. 找到已给出的刷新得分过程，圈出读取全局得分。
2. 读出连接文字“得分：”与数值的作用。
3. 在后续减分与归零事件结尾都调用这个已给过程。

提问：这个过程需要重新定义三次吗？

参考：不需要，同一个定义可被多个事件调用；本课先会使用，详细封装在第13课学习。

### 任务3：补齐减分与归零

1. 添加MinusButton.Click，把得分设为max(0,得分-1)，再刷新。
2. 添加ResetButton.Click，把得分设为0，再刷新。
3. 从0减两次，再加5次、归零、加1次，写下预期和实测。

提问：只把ScoreLabel.Text改成0，重置完成了吗？

参考：没有，全局得分仍是旧值；下一次加分可能把旧分数显示回来。必须清变量再刷新。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| ScoreLabel | Label | 显示当前积分 |
| AddButton | Button | 加1 |
| MinusButton | Button | 减1 |
| ResetButton | Button | 归零 |

- 当 `AddButton.Click`：得分←得分+1；刷新得分。
- 当 `MinusButton.Click`：得分←max(0,得分-1)；刷新得分。
- 当 `ResetButton.Click`：得分←0；刷新得分。

## 过程定义的教学核对

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 每次加分都为1 | 检查是否固定写1，而没有读取旧得分。 |
| 变量已改变，标签慢一次 | 把刷新调用放在赋值之后。 |
| 归零后旧分数回来 | 检查归零是否清全局变量。 |

## 分层与评价

- **基础：**完成加、减、归零，能解释先改数据后显示。
- **提高：**把一次加分改成2，重新写三次连续点击的测试结果。
- **拓展：**为计分器加上挑战名称和规则说明；不把运行变量误当永久保存。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 旧得分是4，执行得分←得分+1后是多少？
   参考：5；先读4并加1，再写回。
2. 为什么标签改0不代表得分归零？
   参考：标签是显示，变量仍可能保存旧值。
3. 怎样测试最低0分？
   参考：先归零，再连续减分至少两次，检查变量与标签均为0。
