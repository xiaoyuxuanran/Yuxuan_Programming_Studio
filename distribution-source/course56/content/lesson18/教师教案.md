# 第18课｜弹球与碰撞

**项目：反弹与目标命中练习　时长：90分钟　配套课件：24页**

## 学习目标与达标证据

1. 把EdgeReached提供的edge参数传给Bounce。
2. 同时检查运行中和碰撞对象，只有目标碰撞计分。
3. 补真正重置，并分开验证反弹、命中与暂停。

## 示例边界

运动弹球碰边反弹，运行中碰静止目标加1分并移动目标。暂停把速度设0；归零重开同时停止、清得分并恢复位置。

Class版已有变量、移动目标、刷新得分和按钮入口，重置已包含位置和停止，但缺得分清零。学生补EdgeReached、CollidedWith及这条清零，不需自己重写整套游戏。

## 核心任务与参考答案

### 任务1：补上边缘反弹

1. 导入Class版，添加PlayBall.EdgeReached。
2. 调用PlayBall.Bounce，把事件参数edge接进去。
3. 分别观察上、下、左、右边反弹，确认得分不变。

提问：为什么把Heading固定设180不能处理所有边？

参考：180只向左，不会根据实际碰边计算反射，上下边也会出错。

### 任务2：只给目标命中计分

1. 添加PlayBall.CollidedWith。
2. 条件为运行中且other=TargetBall组件；通过后得分+1、刷新、移动目标。
3. 测试目标命中与碰边，记录哪一种会加分。

提问：为什么碰边不应通过CollidedWith计分？

参考：碰边由EdgeReached处理；规则规定只有碰到指定TargetBall才命中，边缘不是目标。

### 任务3：补清零并回归测试

1. 找到已有重置过程，在刷新前设置得分为0。
2. 加分后暂停，检查Speed0且分数保持。
3. 点归零重开，确认小球停在起点、显示0，再重新开始。

提问：重置已经移动回起点，还缺得分归0会怎样？

参考：位置新了但旧得分仍保留，刷新会再次显示旧命中数。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| GameCanvas | Canvas | 弹球活动区域 |
| PlayBall | Ball | 运动弹球 |
| TargetBall | Ball | 静止目标 |
| StartButton | Button | 开始暂停 |
| ResetButton | Button | 归零重开 |
| ScoreLabel | Label | 显示命中次数 |

- 当 `PlayBall.EdgeReached`：PlayBall.Bounce(edge)。
- 当 `PlayBall.CollidedWith`：若运行中且other=TargetBall：得分+1；刷新得分；移动目标。
- 当 `StartButton.Click`：运行中取反；Speed为5或0；更新按钮。
- 当 `ResetButton.Click`：重置。

## 过程定义的教学核对

- `移动目标`：TargetBall.MoveTo(random整数20..Canvas.Width-50,random整数20..Canvas.Height-50)。
- `刷新得分`：ScoreLabel.Text←命中次数与得分。
- `重置`：Speed0；运行中false；得分0；Ball.MoveTo(30,60)；移动目标；刷新得分。

请同时对照上方“三个工程版本”区分已给结构与学生任务，不把完整支架重复布置为缺失内容。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 弹球到边粘住 | 检查是否添加EdgeReached并传edge。 |
| 碰任意对象都加分 | CollidedWith需要检查other为目标组件。 |
| 暂停还在加分 | 计分条件遗漏运行中。 |
| 新位置显示旧分数 | 重置要先清变量再刷新。 |

## 分层与评价

- **基础：**完成边缘反弹、目标计分与得分清零。
- **提高：**调整初始Heading或Speed，记录命中体验但保留暂停规则。
- **拓展：**添加第二种目标前先规定不同分值，并用other区分对象。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. Bounce需要哪个事件参数？
   参考：EdgeReached的edge。
2. other要与文字“TargetBall”比较吗？
   参考：不是，与TargetBall组件引用比较。
3. 为什么暂停时还要保护计分逻辑？
   参考：Speed0停止主动运动，但规则仍应明确只有运行状态允许计分，避免其他事件导致误计。
