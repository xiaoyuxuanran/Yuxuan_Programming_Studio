# 第9课｜让 APP 学会判断

**项目：阅读目标判断器　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 完整答案 | YXCourse09.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | YXCourse09Class.aia：保留global 目标、检查时长：合法性检查和待修的>比较、CheckButton.Click；将>改为≥，使20分钟达标；补齐未达标分支的差值显示；添加 ResetButton.Click。 |
| 纯界面起始版 | YXCourse09Starter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 解释比较积木产生真或假，并用if选择一条反馈。
2. 用≥包含刚好20的情况，完成目标-时长差值。
3. 使用19、20、21及无效输入进行边界测试。

## 示例边界

输入本次阅读分钟数，与20分钟目标比较。达到或超过目标时显示达标；未达到时显示还差几分钟。非数字、空白与负数得到明确提示。

Class版故意把边界写成>20，并把未达标差值留为占位，供学生定位修复。输入合法性检查和提交入口已给；本课不保存每日记录，也不把阅读时长当阅读质量评判。

## 核心任务与参考答案

### 任务1：找到边界故障

1. 导入Class版，用19、20、21分别作预测与测试。
2. 在检查时长过程找到“输入>目标”的比较。
3. 把>改为≥，再次测试刚好20。

提问：为什么只测19和21可能发现不了这个故障？

参考：它们在>与≥下结果相同；只有等于目标的20能区分两条规则。

### 任务2：补未达标差值

1. 在未达标分支找到占位反馈。
2. 用目标减输入分钟数，连接“还差”和“分钟。”。
3. 输入8和19，分别检查12分钟与1分钟。

提问：为什么不能把输入减目标作为差额？

参考：未达标时输入小于目标，输入-目标会是负数；还差应为目标-输入。

### 任务3：补重置并检查输入边界

1. 添加ResetButton.Click，清空MinutesBox.Text并恢复初始提示。
2. 测试-1、空白和abc，检查合法性提示。
3. 重置后再输入20，确保仍可完成判断。

提问：输入框改了数字，没点提交就应自动更新吗？

参考：本工程由CheckButton.Click调用检查时长；输入变化本身没有自动提交事件。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| MinutesBox | TextBox | 输入分钟数 |
| CheckButton | Button | 提交判断 |
| ResultLabel | Label | 显示达标或差额 |
| ResetButton | Button | 清空本次输入 |

- 当 `CheckButton.Click`：检查时长。
- 当 `ResetButton.Click`：清输入并恢复提示。

## 过程定义的教学核对

- `检查时长`：输入为非负数字时if时长>=目标显示达标else显示目标-时长；无效提示非负数字。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 20仍显示未达标 | 条件可能仍是>，检查等号。 |
| 显示还差-12分钟 | 差值方向应为目标-输入。 |
| 负数也获得差值 | 先检查输入非负，再进入业务比较。 |
| 重置后仍是旧反馈 | 检查是否同时恢复结果标签。 |

## 分层与评价

- **基础：**修正等号、补差值和重置，覆盖19/20/21。
- **提高：**将目标改为30，重新设计29/30/31的测试。
- **拓展：**把提示改得更鼓励人，同时保留准确数值；不要用时长给人贴能力标签。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. “达到20分钟”应使用>还是≥？
   参考：≥，因为等于20也达到。
2. 输入8分钟，差值是哪一个算式？
   参考：目标20-输入8=12分钟。
3. 为什么要测试目标前后和等于目标三个数？
   参考：前后测试不同分支，等于目标能发现遗漏等号的边界错误。
