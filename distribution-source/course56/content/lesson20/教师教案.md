## 学习目标与达标证据

1. 用待开始、运行、暂停、结束统一管理有效事件。
2. 完成扣生命后判断，确保生命0停止游戏。
3. 按分数档位调整步长并封顶，检查结束与重开恢复。

## 示例边界

接续第19课接苹果。初始3生命，漏接扣1；每5分下落步长加1，最大12。暂停保留位置，生命0结束并显示最终分数，重新开始恢复0分3命。

Class版保留第19课移动、接取与开始/暂停/继续，增加生命与状态面板。学生补漏接扣命、难度公式和结束过程；基础移动无需从头重搭。Clock间隔固定30ms，步长是每次Timer移动量。

## 核心任务与参考答案

### 任务1：漏接先扣生命

1. 在FallClock.Timer的漏接分支，把生命设为生命-1。
2. 若生命≤0调用结束游戏，否则更新面板并重置苹果。
3. 测试三次漏接，检查3→2→1→0，结束后不继续扣。

提问：为什么必须先扣生命再检查是否≤0？

参考：判断的是这次漏接之后的剩余生命；先检查会用旧值，可能多允许一次。

### 任务2：完成递增难度

1. 找到调整难度占位过程。
2. 设置下落步长=min(12,5+floor(得分/5))。
3. 手算4、5、10、35、40分，再核对接物后的变化。

提问：为什么floor(得分/5)而不是直接得分/5？

参考：本规则按完整5分一档，floor取已完成档数；否则每加1分都会出现小数加速。

### 任务3：结束和重新开始分开

1. 结束游戏设置状态结束、Clock关闭、苹果隐藏、开始按钮禁用并显示最终分数。
2. 检查已给的重新开始过程恢复0分3命步长5、待开始与按钮可用。
3. 暂停后继续确认位置不重置；结束后重开确认全状态恢复。

提问：为什么继续不能直接调用重新开始？

参考：继续应保留分数、生命和苹果位置；重新开始会清掉本局进度。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| GameCanvas | Canvas | 接物区域 |
| Fruit | ImageSprite | 下落苹果 |
| Basket | ImageSprite | 玩家篮子 |
| FallClock | Clock | 固定30ms更新 |
| StartButton | Button | 开始暂停继续 |
| ResetButton | Button | 重新开始 |
| ScoreLabel | Label | 得分 |
| LivesLabel | Label | 剩余生命 |
| HintLabel | Label | 状态与操作提示 |

- 当 `StartButton.Click`：待开始→运行并生成苹果；运行→暂停；暂停→运行；结束态不响应。
- 当 `FallClock.Timer`：仅运行态移动苹果；漏接生命-1；生命<=0则结束，否则重置苹果。
- 当 `Fruit.CollidedWith`：运行且碰篮子：得分+1；调整难度；更新面板；重置苹果。
- 当 `ResetButton.Click`：重新开始。
- 当 `GameCanvas.Dragged`：移动篮子(currentX)。

## 过程定义的教学核对

- `更新面板`：显示得分、生命、当前状态。
- `重置苹果`：同第19课随机X并把Y归0。
- `移动篮子(目标X)`：同第19课限制X边界。
- `结束游戏`：状态←结束；Clock关闭；苹果隐藏；StartButton禁用；显示最终得分。
- `重新开始`：得分0；生命3；步长5；状态待开始；计时关闭；按钮恢复。
- `调整难度`：下落步长←min(12,5+floor(得分/5))。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 生命变成负数 | Timer检查运行态，结束时关闭Clock。 |
| 暂停后继续分数归零 | 继续不能调用重新开始。 |
| 结束后看不到最终成绩 | 结束过程不应清得分。 |
| 速度无限增加 | 难度公式保留min(12,…)上限。 |

## 分层与评价

- **基础：**完成扣命、难度和结束，保留第19课基础行为。
- **提高：**调整每档所需分数，并先重新编写边界测试。
- **拓展：**增加一条可解释的新规则，如特殊苹果；先规定与暂停、结束状态的关系。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 5分时步长是多少？35分呢？
   参考：6和12。

3. 结束游戏与重新开始为什么要分开？
