## 课堂支架与实际程序核对

已给结构：

- 缓存与请求变量、结构验证和结束请求
- 完整显示数据、载入缓存和所有事件入口
- 刷新公告、成功更新、失败恢复占位

学生要补或修正：

- 刷新公告设置等待状态并Get
- 成功更新先结构验证，再存info和savedAt并显示网络来源
- 失败恢复保留缓存、标记可能过时并恢复按钮

实际全局变量：`请求中`、`当前URL`、`缓存数据`、`缓存时间`、`响应数据`。

### 过程职责（教师参考）

- `显示数据(数据,来源)`：读取className、announcements、activities；显示来源和最后成功时间。
- `载入缓存`：GetValue info默认空字典，savedAt默认空；有效时显示缓存，否则提示尚无资料。
- `刷新公告`：请求中true；按钮禁用；Url←/api/v1/info；Get。
- `成功更新(数据)`：验证必需结构；保存数据和本地接收时间到TinyDB；显示本次网络结果。
- `失败恢复(原因)`：恢复按钮；保留当前缓存显示；加上内容可能过时与失败原因。

### 三组真实积木截图

1. `载入缓存`：启动读取info与savedAt；显示缓存来源，不自动假装新数据。
2. `成功更新`：先验证再更新变量和TinyDB，坏结构分支不写入。
3. `失败恢复`：恢复按钮并保留缓存内容，提示原因和可能过时。

### 设备与验证边界

使用随课Python课堂服务，HostBox只填电脑局域网IPv4。示例不是公网服务；手机上的127.0.0.1指手机自身。服务的自动测试不等于Android客户端真机联调。 缓存仅代表最后一次有效接收，必须显示本机缓存及可能过时。受控delay/error/invalid-json场景用于课堂排错，不要求物理断网测试。

- 教师电脑运行配套Python标准库API，手机与电脑在可互通的同一局域网。
- 电脑本机可用127.0.0.1；手机必须填写教师电脑局域网IPv4，不能填127.0.0.1。
- HTTP用于隔离的课堂教学数据，不填写真实个人资料；Android明文HTTP兼容性以本平台打包结果实测。

### 共用课堂服务

教师使用随课 `teaching-api/teaching_server.py`；Python 3.8或3.13均可，无需第三方库。先在电脑浏览器核对欢迎接口。手机课堂运行 `python teaching_server.py --host 0.0.0.0`，使用电脑实际局域网IPv4。HostBox仅填IP，例如192.168.1.8；工程初值192.168.1.10是示例，不是固定地址。不要填协议、端口或路径；端口8765和接口路径由积木拼接。手机与电脑需在可互通的教学局域网，手机的127.0.0.1表示手机自身。

可重复故障：先停止当前服务，再加 `--scenario delay`（GET延迟6秒，对照APP超时5秒）、`error`（GET 500）、`empty`（空公告/活动）、`invalid-json`（坏JSON）。恢复用 `--scenario normal`。普通AIA按钮即可触发，不改HostBox为路径，也无需物理断网。POST超时不自动重发；先查结果再决定是否重试。示例仅教学数据，无账号权限系统，勿作为生产留言平台。

## 核心任务与参考答案

### 任务1：阅读启动缓存并补刷新

1. 追踪载入缓存和已有结构验证。
2. 无有效缓存显示尚无资料。
3. 补刷新公告：请求中真、禁用按钮、保存URL、Get。

提问：有缓存为何仍需标来源和时间？

参考：旧资料可能过时，不能让用户误以为刚从网络取得。

### 任务2：补成功更新

1. 先调用公告结构有效检查字段和类型。
2. 通过后才替换缓存变量，生成本机接收时间。
3. TinyDB写info与savedAt，再显示本次网络结果。
4. 坏结构不得覆盖已有好缓存。

提问：HTTP 200能证明内容结构正确吗？

参考：不能，状态成功与业务数据可用需要分别检查。

### 任务3：补失败恢复

1. 有好缓存则继续显示并标可能过时。
2. 无缓存则保持尚无资料，显示失败原因。
3. 恢复请求中假及按钮可用。
4. 用error或invalid-json场景验证，恢复normal后重试。

提问：失败时为什么不把空字典存回缓存？

参考：会毁掉最后一份可用数据；失败只改变状态提示。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| HostBox | TextBox | 教师电脑局域网IPv4地址 |
| RequestButton | Button | 发起本课请求 |
| StatusLabel | Label | 请求与错误状态 |
| InfoLabel | Label | 班级与公告 |
| CacheLabel | Label | 来源与更新时间 |
| ActivitiesView | ListView | 活动 |
| LocalDB | TinyDB | 公告缓存 |
| TimeClock | Clock | 保存接收时刻 |
| Http | Web | 教学HTTP客户端 |

- 当 `Screen1.Initialize`：载入缓存。
- 当 `RequestButton.Click`：若未请求中则刷新公告。
- 当 `Http.GotText`：200且结构有效则成功更新；非200或坏结构失败恢复；结束请求状态。
- 当 `Http.TimedOut`：失败恢复(超时)。
- 当 `Screen1.ErrorOccurred`：失败恢复(通信或格式错误)。

- **提高：**增加用户可设置的自动刷新间隔，并提供关闭入口。

## 出口题参考

1. 缓存时间代表什么？
   参考：本机最后成功接收并保存的时刻，不冒充服务器更新时间。
2. 坏JSON应覆盖旧缓存吗？
   参考：不应，解析或结构验证失败应保留旧缓存。
3. 怎样重复制造超时？
   参考：把课堂服务启动为delay场景，再用原请求按钮。
