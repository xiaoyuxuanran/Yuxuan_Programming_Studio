# 第4课｜我的故事小舞台

**项目：海岛环保三场景故事　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | Course04Story.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | Course04StoryClass.aia：保留CleanButton.Click；完成 RescueButton.Click，显示 RescueScene 并隐藏其余场景；完成两个 Restart 按钮事件，回到 BeachScene。 |
| 纯界面起始版 | Course04StoryStarter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 用VerticalArrangement把同一场景的图片、文字与按钮组织在一起。
2. 通过三个场景的Visible属性切换内容，保证每次只显示一幕。
3. 测试两条故事路线与两个返回按钮，记录场景状态。

## 示例边界

海滩发现垃圾与需要帮助的小海龟。用户可以先清理海滩，或请大人联系专业救助人员；每个分支都能返回开头，再体验另一条路线。

三个场景都在Screen1中，通过Visible切换；本课不新增Screen，也不使用变量或条件判断。两条路线是不同选择，不能把清理沙滩写成代替专业救助。

## 核心任务与参考答案

### 任务1：读取已有的一条路线

1. 导入Course04StoryClass.aia，按组件树找到三个Scene容器。
2. 在组件设计中查看三个Visible初始值，结束后恢复Beach真、其余假。
3. 读CleanButton.Click的三个设置，用纸牌表示谁显示、谁隐藏。

提问：为什么不能只设置CleanupScene.Visible为真？

参考：BeachScene仍为真时开头也会显示，两幕可能同时排在屏幕中；切换要同时处理三个场景。

### 任务2：完成联系救助路线

1. 添加RescueButton.Click。
2. 依次设置BeachScene.Visible为假、CleanupScene.Visible为假、RescueScene.Visible为真。
3. 运行后选择联系救助，检查另外两幕是否完全隐藏。

提问：RescueScene.Visible为假，是删除这个场景吗？

参考：不是。组件和内容仍保留在工程中，只是当前不显示；再次设为真即可显示。

### 任务3：给两个分支加返回入口

1. 添加CleanupRestartButton.Click，设置Beach真、Cleanup假、Rescue假。
2. 给RescueRestartButton.Click设置同样的三个值。
3. 依次测试开头→清理→返回→救助→返回；把一个分支改写成自己的文明校园故事。

提问：两个返回按钮代码相同，可以只做其中一个吗？

参考：不可以。它们是两个不同组件的点击事件；两条路线都需要自己的返回入口。第13课再学习把重复动作封装为过程。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| BeachScene | VerticalArrangement | 开头与两个选择 |
| CleanupScene | VerticalArrangement | 清理行动分支 |
| RescueScene | VerticalArrangement | 专业救助分支 |
| CleanButton | Button | 选择清理沙滩 |
| RescueButton | Button | 选择联系救助 |
| CleanupRestartButton | Button | 从清理路线返回 |
| RescueRestartButton | Button | 从救助路线返回 |

- 当 `CleanButton.Click`：BeachScene.Visible ← False；CleanupScene.Visible ← True；RescueScene.Visible ← False。
- 当 `CleanupRestartButton.Click`：BeachScene.Visible ← True；CleanupScene.Visible ← False；RescueScene.Visible ← False。
- 当 `RescueButton.Click`：BeachScene.Visible ← False；CleanupScene.Visible ← False；RescueScene.Visible ← True。
- 当 `RescueRestartButton.Click`：BeachScene.Visible ← True；CleanupScene.Visible ← False；RescueScene.Visible ← False。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 两个场景同时出现 | 逐项检查三个Visible值，不只看目标场景。 |
| 设计器看不到隐藏场景 | 临时选中对应容器查看Visible；查完恢复初始值，不误改答案初始状态。 |
| 清理路线能返回，救助路线不能 | 检查RescueRestartButton是否有自己的Click事件。 |
| 隐藏容器后仍看到旧图片 | 检查图片是否真放在该Scene内部，而不是Page的同级。 |

## 分层与评价

- **基础：**完成救助与两个返回按钮，四条事件都能解释。
- **提高：**改写一个分支的文字，让人物动机和结果连贯；保留两个返回入口。
- **拓展：**增加第四个场景，同时为所有切换事件补上第四个Visible值并扩充测试表。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 切换到救助场景时，三个Visible应是什么？
   参考：Beach假、Cleanup假、Rescue真。
2. Visible为假与删除组件有什么不同？
   参考：隐藏保留组件和内容；删除会从工程中移除。
3. 怎样证明没有遗漏返回入口？
   参考：分别从两个分支返回，再走另一条路线，记录每一步唯一显示的场景。
