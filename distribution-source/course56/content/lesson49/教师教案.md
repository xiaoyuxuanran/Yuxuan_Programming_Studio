## 学习目标与达标证据

1. 一次回调可能只有半条消息。
2. 等待12时收到11不能误清等待。

### 过程职责（教师参考）

- `发送命令`：仅空闲时分配序号，保存原文和时间后发送。
- `处理应答`：校验序号分隔与当前等待匹配，再校验载荷，成功才结束等待。
- `检查超时`：1500ms后同原文最多重试一次，第二次超时报未确认。

### 三组真实积木截图

1. `发送命令`：发送命令已给，供阅读追踪与超时任务使用。
2. `处理应答`：处理应答待补，内部调用已给处理载荷。
3. `检查超时`：检查超时待补，不能在每次Timer都无限发送。

## 核心任务与参考答案

### 任务1：阅读发送过程并追踪序号

1. 发送命令已给，找到等待原文和发送时刻。
2. 一次只留一个等待序号，其他按钮暂禁用。
3. 用12|LED,1加LF手算请求和应答。

提问：TCP可靠为什么还需要应用层确认？

参考：字节有序传送不等于设备业务已经执行并被界面确认。

### 任务2：补匹配应答

1. 按一个竖线拆成两段并校验正整数序号。
2. 只处理等于等待序号的载荷。
3. 载荷有效才清等待、关AckClock并恢复按钮。
4. 旧序号仅记日志，不清除当前等待。

提问：等待12时收到11|OK,LED,1怎么办？

参考：记录旧应答，不影响12号等待。

### 任务3：补最多一次重试

1. 当前连接且有等待，比较SystemTime差值。
2. 达到1500ms且次数0才重发等待原文，次数设1。
3. 再过1500ms仍无确认则停止等待并提示。
4. 禁止重试时分配新序号或改变命令正文。

提问：超时后能直接显示设备没执行吗？

参考：不能，可能执行了但应答没确认，应显示结果未确认并用GET核对。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| HostBox | TextBox | 设备IP |
| ConnectButton | Button | 连接或重连 |
| OnButton | Button | 可靠开灯 |
| OffButton | Button | 可靠关灯 |
| ReadButton | Button | 可靠GET |
| StatusLabel | Label | 待确认、成功或超时 |
| Socket | ClientSocketAI2Ext | TCP扩展 |
| AckClock | Clock | 100ms检查应答超时 |
| TimeClock | Clock | SystemTime读取 |

- 当 `OnButton.Click`：调用发送命令(LED,1)。
- 当 `OffButton.Click`：调用发送命令(LED,0)。
- 当 `ReadButton.Click`：调用发送命令(GET)。
- 当 `Socket.DataReceived`：收到片段(data)。
- 当 `AckClock.Timer`：调用检查超时。
- 当 `Socket.RemoteConnectionClosed`：清等待与缓存，标记断开，禁止自动连续重连。
