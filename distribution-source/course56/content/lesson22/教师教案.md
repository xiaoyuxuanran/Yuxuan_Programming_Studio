# 第22课｜我的原创小游戏或故事

**项目：星星护送参考关卡　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | YXCourse22.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | YXCourse22Class.aia：保留global 状态、开始一局的完整摆位与重开、控制事件入口和障碍反弹、移动主角、结束的占位框架；补齐运行态移动，中心坐标按半径限制边界；添加Hero.CollidedWith，区分Obstacle与Goal；结束过程保存结果、停止障碍并显示参数。 |
| 纯界面起始版 | YXCourse22Starter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 先规定玩家、目标、困难与反馈，完成最小可玩规则。
2. 实现受限移动和运行状态下的对象碰撞判断。
3. 依据同伴操作记录迭代一条规则，保留可靠重开。

## 示例边界

主角从左下向右上目的地移动，连续拖动避开会反弹的障碍。碰障碍失败，碰目标胜利；结束后冻结障碍并保留结果，开始一局恢复位置。作为个人原创作品的参考骨架。

参考角色由Ball表示，没有额外星形图片。为避免点按终点直接瞬移获胜，每个触摸/拖动事件X/Y各最多移动18像素，再按半径限制边界；不是连续路径碰撞算法，仍需真实试玩检查穿越等问题。Class版已有完整开局和反弹，学生补移动、胜负与结束反馈。

## 核心任务与参考答案

### 任务1：补受限的主角控制

1. 导入Class版，补移动主角(x,y)的运行状态检查。
2. 先把每轴目标夹到当前位置±18，再按Radius到画布尺寸-Radius限制。
3. 连续拖向四角，检查主角完整可见；单点远处不能立即到达。

提问：为什么参考游戏不直接把Hero移到触摸坐标？

参考：玩家可直接点终点绕过障碍；每事件限制步幅让控制更连续，但不等于完整连续碰撞检测。

### 任务2：按对象处理胜负

1. 添加Hero.CollidedWith，仅在状态运行时处理。
2. other为Obstacle则调用结束(失败)，为Goal则结束(胜利)。
3. 结束过程保存结果、停止障碍并更新StateLabel和按钮说明。

提问：已经胜利后再遇到障碍，为什么不能改成失败？

参考：本局已结束，事件入口应拒绝非运行状态，保留第一次有效结束结果。

### 任务3：验证重开并作一次迭代

1. 找到已给的开始一局，读主角、障碍、目标位置及速度恢复。
2. 分别失败和胜利后重开，连续三局检查初始状态一致。
3. 请同伴试玩，只调整障碍速度或移动限制的一项，记录修改前后。

提问：调整障碍速度后为什么仍要测试重开？

参考：开始一局可能写有初始速度，若只改运行中某处，重开会恢复旧值；集中初始规则并做回归验证。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| StageCanvas | Canvas | 关卡舞台 |
| Hero | Ball | 玩家 |
| Obstacle | Ball | 移动障碍 |
| Goal | Ball | 目的地 |
| StartButton | Button | 开始与重开 |
| StateLabel | Label | 关卡状态 |

- 当 `StartButton.Click`：开始一局。
- 当 `StageCanvas.Dragged`：移动主角(currentX,currentY)。
- 当 `StageCanvas.Touched`：移动主角(x,y)。
- 当 `Obstacle.EdgeReached`：Bounce(edge)。
- 当 `Hero.CollidedWith`：运行时若other=Obstacle结束失败；若other=Goal结束胜利。

## 过程定义的教学核对

- `移动主角(x,y)`：仅运行时，先限制每次X/Y各变化不超过18，再限制中心坐标在Radius到画布尺寸减Radius之间。
- `开始一局`：状态运行；主角放左下；障碍中心附近；目的地右上；Obstacle.Speed3。
- `结束(结果)`：状态←结果；障碍Speed0；更新提示和按钮。

请同时对照上方“三个工程版本”区分已给结构与学生任务，不把完整支架重复布置为缺失内容。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 点一下终点就赢 | 参考规则需保留每事件步幅限制。 |
| 胜利立刻又失败 | 碰撞入口只允许运行态。 |
| 到边缘只剩半个球 | Ball中心范围应按半径留边。 |
| 重开继承旧位置或速度 | 所有角色和状态集中在开始一局恢复。 |

## 分层与评价

- **基础：**完成移动、胜负、结束，三次重开规则一致。
- **提高：**依据同伴测试修改一条难度规则并提供前后操作证据。
- **拓展：**原创故事可替换游戏骨架，但仍要有明确状态、选择结果和重新开始；保留来源说明。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. Ball与ImageSprite的边界公式为什么不同？
   参考：本课Ball以中心为坐标，需留Radius；第17课图片用左上位置，需留完整宽高。
2. 每轴最多18是否表示斜向总距离最多18？
   参考：不是，X和Y可各变18；规则是每轴限制，不是总距离限制。
3. 一条有用的试玩反馈应写什么？
   参考：具体操作、预期、实际、修改位置和复测结果。
