# 第6课｜第一次创意改编

**项目：校园兴趣指南　时长：90分钟　配套课件：24页**

## 课前准备

本课采用“体验—预测—制作—改编—分享”的节奏。先向学生发课堂支架版，完成后再对照答案。纯界面版用于课后重建，避免90分钟都用于重复搭界面。

| 版本 | 内容 |
| --- | --- |
| 完整答案 | Course06Clubs.aia：完整参考答案，含本课全部交互。 |
| 课堂支架 | Course06ClubsClass.aia：保留SportsButton.Click；完成 ArtButton.Click 与 CodeButton.Click；完成 ResetButton.Click；自选一种兴趣改写推荐内容。 |
| 纯界面起始版 | Course06ClubsStarter.aia：组件、初始属性与素材齐全，没有积木。 |

运行使用教师已配置的Android设备或模拟器；组件设计器不执行点击逻辑。无设备时仍可做积木分析，但任务单的运行结果须写“待测”。

## 学习目标与达标证据

1. 区分保留的交互结构与自己改变的主题、内容和界面。
2. 完成艺术、编程与重置事件，同步更新建议标题与理由。
3. 根据同伴测试修改作品，并用AIA和改编说明表达学习过程。

## 示例边界

用户从运动、艺术、编程三个方向选择，APP显示固定的校园活动建议与理由；重新选择恢复提示。学生在此基础上改成自己的校园、家庭或阅读指南。

它不是兴趣测评，也不推断用户能力。建议由作者预先编写，点击只选择对应文案。本课整合前五课事件、属性与布局，不要求新增条件或变量。

| 45–60 | 13–16 | 组织编程与重置，先预测顺序。 | 完成其余事件，填写路径测试。 | 所有选择及恢复均完整。 |

## 核心任务与参考答案

### 任务1：读出参考作品的骨架

1. 导入Course06ClubsClass.aia，体验或预测运动按钮。
2. 在SportsButton.Click中找出RecommendationLabel.Text与ReasonLabel.Text。
3. 在纸上写两列：保留的交互方法、准备改变的主题内容。

提问：把运动按钮的文字改成阅读，就已经完成完整改编了吗？

参考：还不够。建议标题、理由和相关界面提示也要与阅读主题对应，并测试点击后的实际结果。

### 任务2：补齐两个选择和重置

1. 添加ArtButton.Click，设置创意美术角及对应理由。
2. 添加CodeButton.Click，设置创意编程社及对应理由。
3. 添加ResetButton.Click，同时恢复两个标签的初始文字；按不同顺序测试。

提问：为什么建议标题与理由需要一起设置？

参考：它们表达同一个选项的结果；只改一个会留下上次选择的信息，产生前后不一致。

### 任务3：制作自己的指南并留下证据

1. 确定给谁使用，选校园活动、阅读或家庭协作中的一个主题。
2. 至少改一个完整选项：按钮Text、建议标题、理由与首页提示保持一致。
3. 请同伴不听解释使用，记录一条反馈并修改；导出个人AIA，写清保留与新增。

提问：怎样说明作品既使用了参考工程，又有自己的设计？

参考：如实写明来源与保留的结构，指出自己修改的用户、文案、布局或行为，并提供前后测试证据；不把参考工程原样当原创提交。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| ChoicesRow | HorizontalArrangement | 并排呈现三个方向 |
| SportsButton | Button | 选择运动 |
| ArtButton | Button | 选择艺术 |
| CodeButton | Button | 选择编程 |
| RecommendationLabel | Label | 显示建议标题 |
| ReasonLabel | Label | 说明为什么可以尝试 |
| ResetButton | Button | 恢复重新选择的提示 |

- 当 `SportsButton.Click`：RecommendationLabel.Text ← 试试运动挑战站；ReasonLabel.Text ← 和同伴练习跳绳或投球。先确认场地安全，按老师的安排热身。。
- 当 `ArtButton.Click`：RecommendationLabel.Text ← 试试创意美术角；ReasonLabel.Text ← 用纸笔设计一张作品海报。选择两种主色，把最重要的信息放大。。
- 当 `CodeButton.Click`：RecommendationLabel.Text ← 试试创意编程社；ReasonLabel.Text ← 把一句问候变成互动名片，再给作品添加声音或新的故事场景。。
- 当 `ResetButton.Click`：RecommendationLabel.Text ← 选择一个方向，看看参考建议。；ReasonLabel.Text ← 这是根据你点击的选项显示的固定建议。你可以修改文案，加入自己的校园活动。。

## 常见问题

| 现象或误解 | 排查提示 |
| --- | --- |
| 只改按钮文字，结果仍是旧主题 | 同时核对该按钮事件里的两个文本值及初始提示。 |
| 重置只清了推荐标题 | ReasonLabel也必须恢复初始解释。 |
| 把固定建议称为智能分析 | 本工程没有个人数据分析，只按按钮显示预写建议。 |
| 改编过程中覆盖原文件 | 先另存个人工程，保留参考来源与自己的导出文件。 |

## 分层与评价

- **基础：**完成所有选择与重置事件，标题、理由成对变化。
- **提高：**完成一项有用户理由的主题改编，并根据同伴反馈修改一次。
- **拓展：**添加一个新方向，或结合第4课容器切换做详细介绍；同步补齐对应测试。

建议功能与规则4分、概念解释2分、测试修正2分、工程保存2分。未完成设备运行的项目，运行分保持待评。

## 出口题参考

1. 本课的建议来自哪里？
   参考：来自作者预先写入按钮事件的固定文案；不是APP自动测出能力。
2. 一次选择为什么要更新两个标签？
   参考：让建议标题与理由对应同一选项，避免上次内容残留。
3. 一份诚实的改编说明应包括什么？
   参考：参考来源、保留结构、自改部分、修改理由和至少一条测试证据。
