## 课堂支架与实际程序核对

已给结构：

- 全部变量
- 移动球边界限制、触障复位、开始
- 方向回调与触摸模式入口
- 模式切换和设备能力检查
- 映射过程返回0占位

学生要补或修正：

- 映射实现2°死区、除5缩放、±6上限
- 添加MoveClock.Timer的X+vx、Y+vy移动
- 添加PlayerBall.CollidedWith：碰墙复位，碰目标停止并胜利

实际全局变量：`运行中`、`模式`、`vx`、`vy`。

### 过程职责（教师参考）

- `映射(角度)`：绝对值<2返回0，否则返回max(-6,min(6,角度/5))。
- `移动球(x,y)`：中心坐标限制到半径..宽高减半径。
- `开始`：Player放左下；Goal右上；运行中true；计时开；vx vy清0。
- `触障复位`：回到起点；vx vy清0。

### 三组真实积木截图

1. `映射`：映射是带返回值过程，Class返0占位。角度恰为2不在小于2的死区内。
2. `MoveClock.Timer`：速度由方向回调保存。移动球过程已给边界限制，不要在两个入口重复写不同边界规则。
3. `PlayerBall.CollidedWith`：Wall为实际1×1纯色PNG拉伸的障碍；不是品牌图标。触摸模式已给入口，胜利和重开仍须按规则检查。

### 设备与验证边界

倾斜roll/pitch轴向和符号需在目标竖屏手机校准。wall.png为原创纯色障碍资源。触摸替代用于验证游戏规则，不用传感器也能先做逻辑检查。



## 核心任务与参考答案

### 任务1：补映射过程的返回值

1. 找到Class中返回0的映射过程。
2. 绝对角度小于2时返回0。
3. 其余返回max(-6,min(6,角度/5))。
4. 手算0、1、30、-100的结果，再检查积木。

提问：死区与上限分别解决什么？

参考：死区减少近水平时微小漂移；上限限制单次位移过大。

### 任务2：补Clock移动

1. 添加MoveClock.Timer。
2. 仅运行中且为倾斜模式时调用移动球。
3. x为PlayerBall.X+vx，y为PlayerBall.Y+vy。
4. 保持Ball.Speed为0，由过程限制中心坐标。

提问：为何不同时设置Ball.Speed为非零？

参考：会叠加另一套自动运动，难以解释每次位移及碰撞规则。

### 任务3：补碰撞并比较两种输入

1. 添加PlayerBall.CollidedWith。
2. other为Wall时调用触障复位；other为Goal时运行中←假并停Clock。
3. 切到触摸模式验证碰墙和胜利，再测试重开。
4. 传感器方向若相反，先记录设备方向再校准符号。

提问：到达目标后只显示胜利文字够吗？

参考：不够，还应停止运行和Clock，防止胜利后继续移动。

## 组件与程序核对

| 名称 | 类型 | 教学作用 |
| --- | --- | --- |
| MazeCanvas | Canvas | 迷宫区域 |
| PlayerBall | Ball | 受控球 |
| Wall | ImageSprite | 中央障碍 |
| Goal | Ball | 终点 |
| Sensor | OrientationSensor | 读取roll与pitch |
| MoveClock | Clock | 40ms更新 |
| StartButton | Button | 开始重开 |
| ModeButton | Button | 切换倾斜与触摸 |
| StatusLabel | Label | 模式及结果 |

- 当 `Sensor.OrientationChanged`：vx←映射(roll)；vy←映射(-pitch)；具体符号按竖屏安装方向校准。
- 当 `MoveClock.Timer`：运行且倾斜模式时移动球(X+vx,Y+vy)。
- 当 `MazeCanvas.Dragged`：运行且触摸模式时移动球(currentX,currentY)。
- 当 `PlayerBall.CollidedWith`：碰Wall触障复位；碰Goal关闭Clock并显示胜利。
- 当 `ModeButton.Click`：倾斜/触摸互换；清零速度。
- 当 `StartButton.Click`：开始。

## 出口题参考

1. 映射(-100)为什么是-6？
   参考：先除5得到-20，再受下限-6限制。
2. OrientationChanged和Timer各做什么？
   参考：前者采样并保存速度，后者按节奏把速度加到位置。
3. 触摸模式能证明倾斜轴方向正确吗？
   参考：不能，只能先验游戏规则；轴向需要真机校准。
